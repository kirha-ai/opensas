# OpenSAS — open backlog

Known gaps and bugs, filed against the SAS 9.4 documentation. Every item is
either fail-loud today (exit code 2 or 1) or a documented divergence; nothing
here is a silent wrong result that we know of.

House rules for anyone picking one up: `CLAUDE.md`. Settled design decisions:
`docs/decisions.md`. Every fix ships a `test` block or a `tests/corpus/*.sas`
fixture with its expected `.txt`.

State: `TODO` assignable · `DOING @dev` claimed · `PARK` waiting on the human.
Line format: `- [STATE] ID (source, …) — title  [deps: …]  @dev`. The source
paren records what backs the ticket: `doc-finder` = SAS-doc citation, `qa` =
reproduced locally, `perf` = measured, `oracle` = real-SAS run, `GH#N` = user
report. A `(likely: path)` tail is a hint, not a constraint — the dev decides
what it changes.
`needs-oracle` = the in-repo docs do not settle it; a run against real SAS 9.4 does.

- [TODO] PERF-innerloop-charleak (perf; superlinear — largely subsumed by EPIC-charfixedwidth) — a within-row `DO` loop producing CHARACTER temporaries accumulates arena memory linearly in trip count, and goes QUADRATIC (time+RSS) when the string grows. Measured ReleaseFast: fixed `$8` temp `do i=1 to N; x=put(i,8.); end;` → N=1e6 1.28s/640MB, N=1e7 22.4s/6.18GB (RSS ∝ trips for what should be O(1)); growing-cats doubling trips → ×3.5 RSS ×4 wall (quadratic); numeric-only control FLAT 1.97MB (leak is string-specific). Root cause: exec.zig scratch arena (the datastep-oom fix) resets ONLY at the row boundary (~L618), so a DO loop inside one runProgram piles up every put/cats/substr/upcase string result until row end. Target: within-row fixed-width char reuse = O(1) mem. The architectural fix IS EPIC-charfixedwidth (fixed-width owned char cells → in-place assign, drop per-iter temps); do NOT attempt a separate arena hack.  (likely: src/exec.zig)  [deps: EPIC-charfixedwidth]
