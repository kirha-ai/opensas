# OpenSAS — open backlog

Known gaps and bugs, filed against the SAS 9.4 documentation. Every item is
either fail-loud today (exit code 2 or 1) or a documented divergence; nothing
here is a silent wrong result that we know of.

House rules for anyone picking one up: `CLAUDE.md`. Settled design decisions:
`docs/decisions.md`. Every fix ships a `test` block or a `tests/corpus/*.sas`
fixture with its expected `.txt`.

State: `TODO` assignable · `DOING @dev` claimed · `PARK` waiting on the human.
Line format: `- [STATE] ID (source, …) — title  [deps: …]  @dev`. The source
paren records what backs the ticket: `doc-finder` = SAS-doc citation, `qa` =
reproduced locally, `perf` = measured, `oracle` = real-SAS run, `GH#N` = user
report. A `(likely: path)` tail is a hint, not a constraint — the dev decides
what it changes.
`needs-oracle` = the in-repo docs do not settle it; a run against real SAS 9.4 does.

- [PARK] BUG-sqlreportnotgated (dev3 finding during GH#19, CRITICAL-class silent-wrong — needs a HUMAN RULING, not a dev slot) — PROC SQL's `report()` is gated only on NOEXEC/NOPRINT and **never on `diags.hasErrors()`**, so any per-row `catch Value.missing` can feed it a fabricated value and it prints a clean-looking table on STDOUT while the ERROR goes to STDERR, with nothing on stdout marking the output as untrustworthy. Independent of GH#19 and survives its fix — verified with an unrelated producer: `proc sql; select g, max(x) as mx from t group by g order by case when max(x)=3 then lag(x) else 0 end; quit;` → stdout is a confident `g=1 mx=3 / g=0 mx=2` at rc 1, an order produced by an all-missing sort key. WHY PARKED: the doc has a doctrine and it is NOT "emit nothing" — LR: Concepts Ch.8 (Example 8.4) shows SAS KEEPING partial results and protecting the reader two other ways instead: `WARNING: The data set WORK.TEST may be incomplete. When this step was stopped there were N observations and M variables.` plus `WARNING: Data set WORK.TEST was not replaced because this step was stopped.` opensas already honours the not-replaced rule (D-024) but has no listing-side analogue. So the choice is a RULING: emit a PROC SQL "may be incomplete" warning, or gate `report()` on step errors. Suppressing a listing is a stdout change that could move many goldens — decide the policy before spending a dev slot.  (likely: src/sql.zig, docs/decisions.md)
